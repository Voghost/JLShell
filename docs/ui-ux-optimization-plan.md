# JLShell UI 与功能优化计划

## 结论

建议先在现有界面基础上画原型图，再进入代码实现。当前 JLShell 的核心功能已经比较完整：SSH/SFTP、项目与文件夹、凭据库、插件、系统监控、外部 API。下一阶段的重点不是继续堆功能，而是把主界面的信息层级、操作入口和视觉一致性整理好。

## 当前界面观察

主界面已经形成“左侧连接树 + 右侧工作区”的专业工具布局，这个方向是对的，应继续保留。问题主要集中在以下几类：

- 顶部、侧栏、标签栏、系统信息栏层级偏多，用户第一眼会看到很多横向条带。
- 左侧连接区信息量大，但项目切换、搜索、树列表、底部工具栏之间的主次关系还不够清楚。
- 图标按钮多但缺少稳定分组，用户需要记忆每个图标的含义。
- 终端工作区很大，但会话状态、快捷动作、插件入口可以更聚合。
- 偏好设置、项目管理、凭据库、导入等功能已经有价值，但入口和流程可以更像一个完整产品，而不是零散工具。

## 优化目标

1. 保持专业、克制、耐用的工具气质。
2. 降低视觉噪音，让高频动作更快找到。
3. 强化连接管理、终端会话、SFTP、插件之间的工作流。
4. 让主题色只用于强调和状态，不污染普通导航。
5. 为未来 Pro/Team 功能预留位置，比如批量命令、脚本片段、共享连接库。

## 原型图优先级

可以先画 3 套低保真原型，再选择一个方向实现。

### 原型 A：稳妥增强版

保留现有布局，只整理视觉层级。

- 侧栏顶部：项目切换、管理项目、设置分成一行清晰工具区。
- 搜索框下方增加筛选入口：全部、收藏、最近、标签。
- 底部工具栏分组：新增/编辑/删除一组，连接/刷新一组。
- 右侧标签栏压缩高度，让终端区域更突出。
- 系统信息栏合并为轻量状态条，插件入口靠右。

适合短期落地，风险最低。

### 原型 B：工作台增强版

把右侧工作区做得更像 IDE。

- 外层为会话标签。
- 内层为终端、文件、监控、脚本、插件。
- 每个会话顶部显示连接状态、用户、主机、延迟、凭据来源。
- 右上角放会话级动作：分屏、复制连接、重连、断开、更多。

适合中期产品化，能承载更多功能。

### 原型 C：运维控制台版

强调批量管理和自动化。

- 左侧从连接树升级为资源导航：项目、收藏、标签、最近、批量任务。
- 中央默认页展示最近连接、批量命令、脚本片段、系统状态。
- 终端只是其中一个工作区，不再是唯一中心。

适合未来 Pro/Team，但短期改动较大。

## 建议先画的页面

第一轮原型不要画太多，先覆盖核心体验：

1. 主界面：有连接树、有一个活动终端。
2. 空状态/欢迎页：没有打开会话时展示最近连接、快速连接、导入入口。
3. 连接详情/编辑弹窗：让连接、凭据、项目、文件夹关系更清楚。
4. 偏好设置：主题、字体、终端、API、导入、Vault 重新分组。
5. SFTP 页面：本地/远程双栏、路径栏、传输队列。
6. 插件页面：已安装插件、会话插件、插件权限。

## 功能优化建议

### 连接管理

- 增加收藏、最近连接、标签筛选。
- 支持连接详情侧边抽屉，减少频繁打开编辑弹窗。
- 支持连接健康状态：最近成功、失败、主机密钥状态、凭据状态。
- 导入后提供整理向导：合并重复连接、批量分配项目和文件夹。

### 终端与会话

- 增加命令面板：快速打开连接、执行脚本、切换主题、打开设置。
- 增加会话级快捷动作：重连、复制连接、新建同主机会话、分屏。
- 增加会话恢复：程序重启后恢复上次打开的连接列表。
- 增加命令片段入口，为后续 Pro 功能铺路。

### SFTP

- 增加传输队列，显示上传/下载进度、失败重试。
- 路径栏支持面包屑和复制路径。
- 右键菜单补齐常用动作：复制远程路径、在终端 cd 到此目录。

### 插件与 API

- 插件页增加权限说明：SSH、SFTP、凭据、本地文件、外部网络。
- API 设置页展示 Token 状态、端口、最近调用、启停状态。
- 插件快捷入口可以固定到系统信息栏右侧，但数量要可控。

### 偏好设置

- 改成左侧分类导航：通用、外观、终端、连接、Vault、插件、API、导入。
- 把主题色、字体、字号、终端字体分清楚。
- 每个设置项给出即时预览，减少试错。

## 视觉设计方向

- 使用中性背景，主题色只用于选中、焦点、主按钮和关键状态。
- 侧栏、标签栏、工具栏都保持低对比，不抢终端内容。
- 图标按钮统一尺寸和 hover 状态，危险操作使用独立颜色。
- 标签栏高度保持克制，避免压缩终端空间。
- 亮色主题优先保证边界、图标、文本对比度。

## 实施顺序

### 第 1 阶段：原型

- 基于当前截图画低保真原型。
- 先画主界面、欢迎页、偏好设置三张。
- 输出静态 HTML 或 Figma 风格图，先确认方向，不写 JavaFX 代码。

### 第 2 阶段：视觉整理

- 统一间距、字号、按钮尺寸、标签栏高度。
- 精简主界面横向条带。
- 修复亮色/暗色主题不一致。

### 第 3 阶段：高频工作流

- 加收藏、最近连接、标签筛选。
- 加命令面板和会话快捷动作。
- 优化 SFTP 传输队列。

### 第 4 阶段：产品化

- 优化偏好设置、插件管理、API 状态页。
- 加新手引导和空状态。
- 为 Pro/Team 功能预留入口。

## 下一步建议

先做一张“主界面稳妥增强版”原型图，保持现在的结构，只调整布局、密度和入口。确认舒服后，再画欢迎页和偏好设置。这样最不容易把已有功能改乱，也能快速判断审美方向是否正确。
