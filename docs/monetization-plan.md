# JLShell 盈利计划

## 产品定位

JLShell 适合定位为“面向开发者、运维和小团队的现代 SSH/SFTP 工作台”。它不只是终端工具，而是把连接管理、项目分组、凭据库、SFTP、插件系统和本地 JSON-RPC API 组合在一起。后续盈利的核心不应是限制基础 SSH 功能，而是围绕效率、自动化、团队协作和企业安全能力收费。

## 目标用户

第一批用户应聚焦个人开发者、独立运维、小型研发团队和需要管理多台服务器的技术负责人。他们愿意为三个结果付费：更快连接和定位服务器、更安全地管理凭据、更方便地把终端能力接入脚本或 AI 工具。

中后期再扩展到中小企业和内部平台团队，重点卖团队连接库、权限、审计、策略配置、私有插件和部署支持。

## 推荐商业模式

采用“免费核心 + Pro 买断/订阅 + 团队版订阅 + 企业支持”的组合。

| 版本 | 目标用户 | 收费点 |
| --- | --- | --- |
| Free | 个人用户、开源传播 | SSH/SFTP、连接管理、基础 Vault、基础插件 |
| Pro | 重度个人用户 | 高级自动化、批量操作、脚本片段库、更多主题和生产力插件 |
| Team | 小团队 | 团队连接库、共享 Vault、成员权限、同步、审计日志 |
| Enterprise | 企业客户 | 私有部署、SSO、策略控制、插件审核、定制开发和支持 |

建议早期避免一上来做复杂授权服务。可以先做 Pro 许可证文件或邮箱激活，等用户量稳定后再接支付、账户和同步服务。

## 可收费功能路线

### Pro 功能

- 批量 SSH 命令：对多个连接同时执行命令，带结果汇总和失败重试。
- 脚本片段库：保存常用命令、参数模板、变量输入和执行历史。
- 高级导入导出：连接、项目、主题、插件配置的一键迁移。
- 自动化工作流：打开连接后自动执行初始化命令、打开 SFTP、启动监控插件。
- 高级 UI：多工作区布局、会话搜索、命令历史搜索、更多专业主题。

### Team 功能

- 团队项目空间：共享连接、文件夹和标签。
- 共享凭据库：按项目或角色授权，避免明文传递密码。
- 权限模型：成员只能访问被授权的项目、连接或凭据。
- 审计日志：记录连接、命令执行、凭据读取、导入导出等行为。
- 云同步或自托管同步：优先支持自托管，降低企业安全顾虑。

### Enterprise 功能

- SSO/OIDC、LDAP、SCIM 成员同步。
- 统一策略：禁用自动信任主机密钥、强制主密码、限制外部 API。
- 插件签名与白名单：只允许加载被企业批准的插件。
- 离线授权和内网部署包。
- 定制插件、迁移支持、优先修复 SLA。

## 插件市场策略

JLShell 的插件系统是差异化资产。短期先做“官方精选插件”，不要急着开放完整市场。

第一阶段推出官方 Pro 插件：批量命令、日志查看、系统监控增强、Docker/Compose 面板、Kubernetes 只读面板、Nginx/应用日志 tail 工具。第二阶段允许第三方插件提交，但需要签名、审核和权限声明。第三阶段再考虑插件分成，比例可从 70/30 或 80/20 开始。

插件权限必须清晰展示：是否访问 SSH 会话、SFTP、凭据库、外部网络、本地文件。安全感会直接影响付费转化。

## 定价建议

早期建议简单定价，方便验证：

- Pro：一次性买断 19-39 美元，或 3-5 美元/月。
- Team：每人每月 6-12 美元。
- Enterprise：按年报价，从 999 美元/年起，包含支持和离线授权。

如果用户主要来自国内，可同步提供人民币价格：Pro 99-199 元买断，Team 39-69 元/人/月。早期不要频繁涨价，先用“早鸟终身授权”换第一批真实用户反馈。

## 增长路径

### 0-3 个月：验证付费意愿

- 做官网落地页，明确卖点：跨平台 SSH/SFTP、项目管理、Vault、插件、API 自动化。
- 发布可下载版本，收集安装量、启动量、活跃连接数、插件使用率。
- 建立反馈入口：GitHub Discussions、微信群/Discord、内置反馈按钮。
- 推出 Pro 等候名单，不急着收费，先收集邮箱和用户场景。

### 3-6 个月：推出 Pro

- 完成许可证机制和 Pro 功能开关。
- 优先发布批量命令、脚本片段库、高级导入导出。
- 提供 14 天试用，过期后回到 Free，不影响基础连接。
- 写迁移文档：从 MobaXterm、Xshell、Termius 等工具迁移到 JLShell。

### 6-12 个月：团队协作

- 做团队连接库和共享 Vault 的最小闭环。
- 先支持自托管同步服务，企业更容易接受。
- 加审计日志和权限分组。
- 寻找 3-5 个真实团队做设计伙伴，换取案例和年度订阅。

### 12 个月后：企业化

- 推出 Enterprise：SSO、策略、插件白名单、离线授权。
- 建立插件签名和审核流程。
- 提供付费支持、私有插件开发和迁移服务。

## 风险与原则

- 不要限制基础 SSH/SFTP，否则会伤害口碑和传播。
- 凭据库、同步、插件权限必须优先做安全设计，否则商业化会被信任问题卡住。
- 外部 API 是亮点，也有安全风险：Team/Enterprise 应提供策略开关、Token 轮换和审计。
- 插件市场不要过早开放，先把官方插件质量做高。
- 商业版功能要围绕“节省时间、降低风险、支持团队”，不要只卖皮肤和小装饰。

## 当前最推荐的下一步

先做 Pro 的三个高价值功能：批量命令、脚本片段库、配置导入导出。它们与现有架构最贴近，开发成本相对可控，也最容易让用户感知价值。并行准备官网、下载页、反馈入口和早鸟许可证机制。等个人 Pro 有真实付费后，再投入团队同步和企业能力。
