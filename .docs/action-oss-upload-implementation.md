# Action Artifact 上传 OSS 实现说明

本文档面向后续接手实现的 agent，目标是在当前 Action 发布回调基础上补齐：

1. Action 与网站加密通信。
2. 网站收到 Action 回调后，主动下载 Action artifact。
3. 网站把 artifact 上传到阿里云 OSS 指定目录。
4. 网站把 OSS 公开 URL、大小、SHA-256 入库。
5. 后台控制哪些版本和哪些包展示，未展示包不能被公开更新 API 返回。

## 当前状态

已经实现：

- Action 回调入口：`POST /api/v1/actions/releases`
- HMAC-SHA256 签名校验：
  - `X-JLShell-Timestamp`
  - `X-JLShell-Signature`
- Action 入库服务：`ActionReleaseService`
- 版本可发布/隐藏：`release_versions.status`
- 资产可展示/隐藏：`release_assets.visible`
- 后台资产展示/隐藏按钮。
- 公开 API 只返回 `visible=true` 的资产。

尚未实现：

- 服务端主动从 `downloadUrl` 下载 artifact。
- 服务端上传 artifact 到 OSS。
- OSS SDK 依赖、配置类和上传服务。
- 下载/上传过程中的大小和 SHA-256 校验。

## 目标接口

### `POST /api/v1/actions/releases`

保持当前接口路径不变。

请求头：

```text
Content-Type: application/json
X-JLShell-Timestamp: <unix seconds>
X-JLShell-Signature: sha256=<hex hmac>
```

签名内容：

```text
<timestamp>.<raw-json-body>
```

签名算法：

```text
HMAC-SHA256(JLSHELL_ACTION_WEBHOOK_SECRET, timestamp + "." + rawBody)
```

签名校验要求：

- `JLSHELL_ACTION_WEBHOOK_SECRET` 为空时返回 `503`。
- timestamp 非数字时返回 `401`。
- timestamp 超出 `JLSHELL_ACTION_SIGNATURE_TOLERANCE_SECONDS` 时返回 `401`。
- 签名不匹配时返回 `401`。
- 必须基于 raw body 校验，不能基于重新序列化后的 JSON。

### 请求体

```json
{
  "version": "0.1.35",
  "channel": "stable",
  "updateType": "jar",
  "title": "JLShell v0.1.35",
  "summary": "Release generated by CI",
  "releaseNotes": "更新说明",
  "mandatory": false,
  "requiresFullInstaller": false,
  "minLauncherVersion": "0.1.0",
  "publish": false,
  "assets": [
    {
      "os": "windows",
      "arch": "x64",
      "packageType": "msi",
      "fileName": "JLShell-0.1.35-win-x64.msi",
      "downloadUrl": "https://github.com/org/repo/actions/runs/123/artifacts/456",
      "url": "",
      "size": 12345678,
      "sha256": "hex-sha256",
      "visible": false
    }
  ]
}
```

字段语义：

- `version`：版本号，作为 upsert key。
- `publish=false`：创建或更新为后台草稿，不公开版本。
- `publish=true`：直接发布版本。
- `assets[].visible=false`：资产入库但不展示；公开 API 不返回该资产。
- `assets[].url`：已经上传 OSS 的最终公开 URL。若存在，可以直接入库，不需要服务端上传。
- `assets[].downloadUrl`：Action artifact 下载 URL。若 `url` 为空，服务端应下载此 URL 并上传 OSS。
- `assets[].sha256`：Action 侧计算出的 SHA-256，服务端下载后必须重新计算并比对。
- `assets[].size`：Action 侧产物大小，服务端下载后建议比对；如果请求为 `0`，服务端以实际下载大小为准。

### 响应体

沿用当前 `ActionReleaseResponse`：

```json
{
  "release": {
    "id": "...",
    "version": "0.1.35",
    "status": "draft",
    "assets": []
  },
  "acceptedAssets": 3,
  "message": "accepted as draft"
}
```

实现上传后建议扩展 `message`，标明上传数量：

```text
accepted as draft, uploaded 3 assets
```

## OSS 配置

新增配置项建议放在 `JlshellSiteProperties` 下，环境变量透传到 `docker-compose.prod.yml` 和 `deploy/nas.env.example`：

```env
JLSHELL_OSS_ENABLED=true
JLSHELL_OSS_REGION=cn-hangzhou
JLSHELL_OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
JLSHELL_OSS_BUCKET=jlshell
JLSHELL_OSS_RELEASE_PREFIX=releases
JLSHELL_OSS_PUBLIC_BASE_URL=https://cdn.example.com/jlshell
JLSHELL_OSS_USE_CNAME=false
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
```

说明：

- `JLSHELL_OSS_RELEASE_PREFIX` 已存在，默认 `releases`。
- `JLSHELL_OSS_PUBLIC_BASE_URL` 已存在，用于生成最终公开 URL。
- `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` 推荐沿用阿里云 SDK 的环境变量方式。
- 如果使用自定义域名/CNAME，设置 `JLSHELL_OSS_USE_CNAME=true`，并确保 `JLSHELL_OSS_ENDPOINT` 是自定义域名。

对象 key 规则：

```text
<JLSHELL_OSS_RELEASE_PREFIX>/<version>/<fileName>
```

例：

```text
releases/0.1.35/JLShell-0.1.35-win-x64.msi
```

公开 URL 规则：

```text
<JLSHELL_OSS_PUBLIC_BASE_URL>/<JLSHELL_OSS_RELEASE_PREFIX>/<version>/<fileName>
```

注意去掉多余 `/`，避免出现双斜杠。

## 阿里云 OSS SDK 接入建议

官方文档建议 Maven 依赖：

```xml
<dependency>
    <groupId>com.aliyun</groupId>
    <artifactId>alibabacloud-oss-v2</artifactId>
    <version><!-- 查询最新版本 --></version>
</dependency>
```

实现建议：

1. 新增 `OssStorageProperties` 或扩展 `JlshellSiteProperties`。
2. 新增 `OssStorageService`：
   - `StoredObject uploadReleaseAsset(String version, String fileName, Path localFile, String contentType)`
   - 返回 `objectKey`、`url`、`size`、`sha256`。
3. 新增 `ArtifactDownloadService`：
   - 下载 `downloadUrl` 到临时文件。
   - 支持可选请求头，例如 GitHub artifact 需要 token 时可扩展。
   - 设置下载大小上限，防止误下载超大文件。
4. `ActionReleaseService` 处理 asset 时：
   - 如果 `url` 非空：保持现有行为，直接入库。
   - 如果 `url` 为空且 `downloadUrl` 非空：
     - 下载到临时文件。
     - 计算 SHA-256。
     - 校验请求中的 `sha256`。
     - 校验 size。
     - 上传 OSS。
     - 用 OSS URL 入库。
   - 如果两者都为空：返回 `400`。

建议类结构：

```text
backend/src/main/java/com/jlshell/website/storage/ArtifactDownloadService.java
backend/src/main/java/com/jlshell/website/storage/OssStorageService.java
backend/src/main/java/com/jlshell/website/storage/StoredObject.java
backend/src/main/java/com/jlshell/website/config/OssStorageProperties.java
```

## 下载 artifact 的安全要求

必须做：

- 只允许 `https://` 下载 URL，除非显式配置允许内网 HTTP。
- 设置连接超时和读取超时。
- 设置最大下载大小，例如 `JLSHELL_ACTION_ARTIFACT_MAX_BYTES`。
- 下载过程中计算 SHA-256，不能只信任 Action 传值。
- 下载后用 `Files.size` 和请求 `size` 对比。
- 临时文件用 `Files.createTempFile`，finally 删除。
- 不把下载 token、OSS key、签名密钥写入日志。

建议新增配置：

```env
JLSHELL_ACTION_ARTIFACT_MAX_BYTES=1073741824
JLSHELL_ACTION_DOWNLOAD_TIMEOUT_SECONDS=120
JLSHELL_ACTION_ALLOW_HTTP_DOWNLOAD=false
```

GitHub Actions artifact 下载注意：

- 浏览器页面 URL 通常不是稳定的二进制下载地址，优先使用 GitHub REST API 的 artifact download endpoint，或在 Action 侧生成可直接下载的短期 URL。
- 如果下载需要 GitHub token，建议服务端配置 `JLSHELL_ACTION_DOWNLOAD_TOKEN`，下载时附加 `Authorization: Bearer <token>`，不要把 token 拼进 `downloadUrl`。
- 如果后续还要支持 GitLab/Jenkins artifact，可以把下载认证抽象成 provider，例如 `sourceProvider=github|gitlab|jenkins|direct`，第一阶段先支持 `direct` 和 `github` 即可。

## 数据库与展示语义

当前资产表新增：

```sql
visible BOOLEAN NOT NULL DEFAULT TRUE
```

约定：

- 手动后台新增资产默认 `visible=true`。
- Action 推送资产默认 `visible=false`，除非 payload 显式传 `visible=true`。
- `ReleaseDto.publicFrom` 必须过滤隐藏资产。
- `ReleaseService.latestUpdate` 查找 jar/full installer 时必须过滤隐藏资产。
- 后台 `ReleaseDto.from` 显示全部资产。

如果要保存 OSS object key，建议新增迁移：

```sql
ALTER TABLE release_assets ADD COLUMN IF NOT EXISTS object_key TEXT;
ALTER TABLE release_assets ADD COLUMN IF NOT EXISTS source_url TEXT;
```

字段语义：

- `object_key`：OSS 对象 key，例如 `releases/0.1.35/app.jar`。
- `source_url`：Action artifact 原始下载 URL，便于排查，但注意不要存带长期敏感 token 的 URL。

## GitHub Actions 调用示例

当前客户端仓库采用 GitHub Actions 直接上传 OSS 的方式：

- release workflow 下载各平台构建产物。
- 使用 GitHub Secrets 中的 OSS AccessKey 通过阿里云 OSS SDK 上传到 OSS。
- 生成最终公开 URL 后，调用 `POST /api/v1/actions/releases`。
- 回调 payload 中传 `assets[].url`，网站直接入库，不再从 `downloadUrl` 下载。

需要在 GitHub 仓库配置：

Secrets：

```text
OSS_ACCESS_KEY_ID
OSS_ACCESS_KEY_SECRET
JLSHELL_ACTION_WEBHOOK_SECRET
```

Variables：

```text
JLSHELL_OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
JLSHELL_OSS_BUCKET=<bucket-name>
JLSHELL_OSS_RELEASE_PREFIX=releases
JLSHELL_OSS_PUBLIC_BASE_URL=https://<cdn-or-bucket-domain>
JLSHELL_SITE_URL=https://jlshell.oomn.net
```

`JLSHELL_OSS_PUBLIC_BASE_URL` 可不配，workflow 会按 `<bucket>.<endpoint-host>` 推导公开 URL；如果使用 CDN 或自定义域名，建议显式配置。

Action 会额外上传 `jlshell-app-<version>.jar` 作为增量更新包，并在官网中注册三条 jar 资产：

```text
windows / any / jar
linux   / any / jar
mac     / any / jar
```

原因是当前网站 `latestUpdate` 按 `os` 精确匹配 jar 资产，`arch=any` 可匹配所有架构。

Action 侧需要先构造 JSON，再按 raw body 计算签名：

```bash
body="$(jq -n \
  --arg version "$VERSION" \
  --arg title "JLShell $VERSION" \
  --arg fileName "$FILE_NAME" \
  --arg downloadUrl "$ARTIFACT_URL" \
  --arg sha256 "$SHA256" \
  --argjson size "$SIZE" \
  '{
    version: $version,
    channel: "stable",
    updateType: "jar",
    title: $title,
    publish: false,
    assets: [{
      os: "windows",
      arch: "x64",
      packageType: "msi",
      fileName: $fileName,
      downloadUrl: $downloadUrl,
      size: $size,
      sha256: $sha256,
      visible: false
    }]
  }')"

ts="$(date +%s)"
sig="sha256=$(printf '%s.%s' "$ts" "$body" \
  | openssl dgst -sha256 -hmac "$JLSHELL_ACTION_WEBHOOK_SECRET" -hex \
  | awk '{print $2}')"

curl -fS -X POST "$JLSHELL_SITE_URL/api/v1/actions/releases" \
  -H "Content-Type: application/json" \
  -H "X-JLShell-Timestamp: $ts" \
  -H "X-JLShell-Signature: $sig" \
  --data "$body"
```

## 测试清单

后端单元/集成测试：

- 正确签名：`POST /api/v1/actions/releases` 返回 200。
- 错误签名：返回 401。
- timestamp 过期：返回 401。
- secret 未配置：返回 503。
- `url` 非空：直接入库，不下载。
- `url` 为空、`downloadUrl` 非空：下载、校验、上传、入库。
- sha256 不匹配：返回 400，不入库。
- size 不匹配：返回 400，不入库。
- Action 资产默认隐藏。
- 后台可展示/隐藏资产。
- 公开 releases/latest/downloads 不返回隐藏资产。
- 后台 releases 返回隐藏资产。

前端验证：

- 后台 release 列表能看到资产可见状态。
- 点击“展示包”后公开下载 API 可返回该资产。
- 点击“隐藏包”后公开下载 API 不再返回该资产。

部署验证：

- `.env` 中配置 `JLSHELL_ACTION_WEBHOOK_SECRET`。
- `.env` 中配置 OSS bucket、endpoint、public base URL。
- Docker Compose 透传 OSS 环境变量。
- Jenkins/GitHub Action 不打印共享密钥和 OSS AccessKey。

## 交付边界

第一阶段建议只实现 OSS 上传链路，不要顺手改发布策略：

- Action 创建/更新版本。
- Action 上传资产后默认隐藏。
- 管理员人工确认后展示版本和资产。

后续再考虑自动发布规则，例如：

- `publish=true` 且所有 required assets 上传成功才自动发布。
- 对 beta channel 自动展示，对 stable channel 人工审核。
- 后台批量展示同一版本全部资产。
